# 课表入历 v0.3.1

版本标记：实现 .ics 文件自动上传日历，未优化 UI。
这里的“自动上传”指生成 ICS 并衔接系统日历导入流程，仍需用户打开文件及系统确认，不是静默写入 iCloud。用户已反馈 Mac 本地入历跑通；iPhone/iPad 尚待真机验证。

## Mac 双击启动
首次使用需安装 Node.js。双击项目根目录的 `启动课表工具.command`，启动后自动打开默认浏览器，保持终端窗口开启；按 Control+C 停止服务。
若提示无执行权限，在项目目录运行 `chmod +x 启动课表工具.command` 后重试。若提示端口占用，已有工具可直接访问 http://127.0.0.1:4173/；不要重复启动。
Windows 继续使用 `启动课表工具.cmd`。启动工具不会安装依赖，也不会自动向日历添加事件。

## 入历流程与草稿（当前版）
“添加到 Apple 日历”会先保存草稿，再生成包含停课、补课和额外加课的 ICS。Mac 下载后需打开文件并在日历 App 中确认，可选择已有日历，不要求预先新建；iPhone/iPad 尝试打开日历文件，仍待实机验证，失败时使用“仅下载 ICS”或在 Mac 导入。纯静态网页不能静默写入 iCloud，也不能检测系统是否添加成功。本版不包含订阅服务或后台自动同步，重复导入可能重复课程。

草稿自动保存在当前浏览器的 localStorage，包含已登记/候选课程、确认状态、作息、停课和补课设置；图片原文件不保存。可备份和恢复 JSON 草稿。file://、localhost、127.0.0.1 与不同浏览器的存储相互独立，切换前请备份。存储不可用时会提示，损坏的旧草稿不会自动覆盖；多页面冲突时暂停保存。旧版页面刷新前仍须自行保留输入。

测试：`node test-calendar-delivery.cjs`；根目录 `test*.cjs` 为回归测试。以下历史说明中的“刷新清空”已由本节取代。

## 停课日期、调休补课与额外加课
主界面新增停课日历：高亮日期不生成课程，再点击恢复；可手动选日，或载入国家放假安排后继续增减。内置已核实的 2026 年国务院放假调休数据，其他年份提示手动设置。法定模式按第一教学周起 30 周的可用范围载入，跨年不会猜测未内置年份的假期。
国家调休上班日标为“班”，默认沿用当天原课表；学校规定补课时，在“调休补课安排”选择补课日及来源日期。来源采用原始课程的教学周和单双周，替换目标日常规课程，额外加课仍按自己的规则；高亮停课优先于所有课程。停课不顺延教学周。假期取消后再点击法定模式不会覆盖手工修改。
额外加课可指定名称、教师、教室、星期、时间及不连续教学周（如 5,7,9），单独登记并标记“加课”，仍需逐门确认。停课、补课同时作用于预览和 ICS 导出。所有新设置仍仅在页面内存，刷新会清空。
数据来源：[国务院办公厅关于2026年部分节假日安排的通知](https://www.beijing.gov.cn/cs/gncs/zcwj/202603/t20260327_4568275.html)。测试：`node test-adjustments.cjs`、`node test-calendar-options-ui.cjs`（后者需先安装 work/v02-tests 的依赖）。

## 0.3 手机课表识别
自动按同宽彩色课程块定位，排除顶部导航、整行提示与底部按钮；无需手动裁剪。浅色底彩色字与深色底白字分别增强，逐列识别星期，逐块识别中英文，连接窄屏换行课程名。同名课程合并，不同星期、非相邻时段保留编辑。

本地真实 OCR 回归：所提供手机截图为 6 门课 / 9 个星期安排，电脑截图为 5 门课 / 8 个星期安排，课程名和星期均符合人工核对。测试通过 Node canvas 适配器调用网页同一识别流程及本地 Tesseract 模型，并非手机浏览器性能测试。手机图部分教室图标误读、被截断的教室号仍需核对；开始/结束时间和学期周数不由截图推测。未验证倾斜实拍、黑白表格及其他学校版式，不能将两张样例结果视为通用准确率。

所有图片仍在本机处理。定位失败时明确提示，不把整屏导航文字登记成课程。刷新网页会清除当前未保存草稿。

## 小字识别补充
教室首行单独放大并用单行模式重读，减少定位图标粘连；后续换行拼接。贴近课块底边的地址不填写，避免把截断数字猜成完整房间号。左侧时间轴单独识别数字和冒号，再按课块位置关联开始时间；结束时间不由下一节开始时间推算，仍须核对。

## 字号优先分界
按用户要求停用“校区词+房间数字”后缀拆分。课程和地点优先根据 OCR 行的字形高度下降、后续小字高度一致性及垂直排列区分，@ 等定位符号辅助。缺少字号差异与符号时不按数字猜分界。
当前手机样例六门课名保持完整，但体育场地点首行重识别仍有误字，需核对。用户最新提供的是候选结果截图，尚缺该课表原图，未验证“电路分析/主南106”的端到端识别；已验证对应字号结构的分界测试。

## 学校作息表与节次
网页新增作息表：上午/下午/晚上各节数和起点、课长、课间；生成后可逐节改时间，确认才启用。午休独立起算。修改作息不自动覆盖已有课程；各时段可编辑起止节次并点击“按节次填时间”。
识图保留节次标签坐标，至少三个一致间距的标签才建立网格；单个数字漏识别时可按已读编号补齐规则网格，不支持不规则行高的任意推算。缺少可靠节次则留空。开始时间与截图冲突时保留核对提示。
真实测试1九个安排的起止节次均符合图片；时间来自测试配置，并非声称与该学校作息一致。包括午休、课间、跨多节、非法时间和网页交互测试。刷新仍会清空作息和草稿。

## 节次登记修复
星期表头未识别时不再删除整个上课安排。保留起止节次与时间，以“星期待确认”显示；用户在时段内补选星期后才能确认导出。此修复解决传递丢失，不代表原图中所有节次都能识别。原图没有可用节次时仍需补填。

## 时间输入双入口
首次打开只显示两个选项：
- 填写学校作息表：进入上午/下午作息录入，确认成功后进入主页面并展开识图。候选区显示自动识别的星期和节次，允许核对修改；仍受原有OCR准确率限制，不能保证每张图均预填。
- 手动输入时间：直接进入主页面识图；跳过表头和时间轴OCR，候选只编辑课名、地点，登记时不导入识别时段。用户在已登记课程选择星期和填写时间。

主页面可返回更换方式或修改作息。已有登记课程保留；进入另一方式会清空未登记候选。识别进行中不能切换方式。test-entry-flow.cjs验证入口、确认门槛及两种模式的候选/登记差异。本轮未上传GitHub。

## 作息表实时编辑
进入作息录入即显示所有节次，行数等于上午与下午节数之和，无折叠和生成按钮。每行固定为节次、上课时间、下课时间。上方参数输入实时重算整表（包括覆盖手动调整），页面已提示先设参数再调整大课间。无效参数或重叠时间禁止确认，确认后才启用新作息。
